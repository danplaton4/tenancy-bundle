<objective>
Ship `TenantAwareFilesystemDecorator` — the per_tenant_adapter-mode (DEC-FILE-MODE opt-in) FilesystemOperator decorator. Unlike the prefix-mode decorator, this one does NOT manipulate paths; instead it routes the entire call to a per-tenant `Filesystem` instance constructed from the tenant's `filesystemConfig.adapter_dsn` (via `AdapterDsnParser` from Plan 24-04) and cached in `LruFilesystemCache` (Plan 24-03).

This is the "S3-bucket-per-tenant" / "regulated-deployment" mode. RESEARCH.md §Architectural Responsibility Map maps the primary tier (decorator) + secondary tiers (LRU cache + DSN parser). Same live-read discipline as Plan 24-05 — long-running workers reuse instances, stale prefix/adapter state would leak across tenants.

Output: 1 new production file + 1 unit-test file flipped from incomplete to passing.
</objective>
