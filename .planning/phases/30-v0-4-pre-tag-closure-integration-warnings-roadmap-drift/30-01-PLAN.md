## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| tenant A context → tenant B context (fan-out loop) | The per-change / per-message loop repeatedly switches TenantContext + the tenant DBAL connection across tenants; a missed save/restore or unclosed connection silently leaks tenant A's data into tenant B's DB or into the request-scoped tenant's later queries. This is the bundle's core security property (CLAUDE.md: a cross-tenant leak is a security incident). |
| request-scoped tenant → fan-out → request-scoped tenant | CR-01: the tenant active when the landlord flush occurred must survive the entire fan-out and be re-instated; CR-02: the connection must be closed after the loop so the next query reconnects under the restored context. |
