<objective>
Replace DBAL 4 `wrapperClass` + `ReflectionProperty` connection switching with a driver-middleware architecture. New `TenantDriverMiddleware` registered via Doctrine's `doctrine.middleware` tag (scoped to the `tenant` connection only) returns a `TenantAwareDriver` whose `connect()` reads `TenantContext` and merges the active tenant's params over the landlord placeholder params before delegating to the wrapped driver. `DatabaseSwitchBootstrapper::boot()` reduces to `$connection->close()` — DBAL's lazy-reconnect path handles the rest. `TenantConnection` and `TenantConnectionInterface` are deleted outright (v0.1 had 2 self-Packagist-downloads; no external users). Closes issues #7 and #8.

Purpose: DBAL 4 resolves the `Driver` at `DriverManager::getConnection()` construction time and stores it immutably on the Connection. `TenantConnection::switchTenant()` uses reflection to mutate `Connection::$params` but cannot touch `$driver` — so with a `sqlite://` placeholder for MySQL tenants, queries handed to the SQLite driver fail. The correct extension point is `Doctrine\DBAL\Driver\Middleware`, which wraps the driver itself. Params mutation happens per-connect() via middleware, the driver stays consistent across tenant switches (same driver family per the placeholder), and `$connection->close()` forces a reconnect that re-enters the middleware with fresh context.

Output: New middleware + driver pair under `src/DBAL/`, DI wiring in `TenancyBundle::loadExtension()`, simplified `DatabaseSwitchBootstrapper`, deletions of `TenantConnection`, `TenantConnectionInterface`, `tests/Unit/DBAL/TenantConnectionTest.php`, rewrites of `DatabaseSwitchBootstrapperTest`, `DatabaseSwitchIntegrationTest`, test kernels (remove `wrapper_class`), and `StubConnectionFactory`. Two new integration tests: wiring assertion + real two-SQLite-file roundtrip.

Commit footer guidance: `Fixes #7` AND `Fixes #8` (one commit, both footers — both issues are the same root cause per CONTEXT).

Create `src/DBAL/TenantAwareDriver.php`:

```php
<?php

declare(strict_types=1);

namespace Tenancy\Bundle\DBAL;

use Doctrine\DBAL\Driver;
use Doctrine\DBAL\Driver\Connection as DriverConnection;
use Doctrine\DBAL\Driver\Middleware\AbstractDriverMiddleware;
use Tenancy\Bundle\Context\TenantContext;

/**
 * AbstractDriverMiddleware subclass invoked on every Connection::connect() reconnect.
 * Reads the active tenant from TenantContext and merges its getConnectionConfig() over
 * the frozen landlord params before delegating to the wrapped driver.
 *
 * 'url' keys in tenant config have no effect: DriverManager parses 'url' into discrete
 * keys BEFORE middlewares wrap the driver. Tenants should expose 'dbname', 'host', 'port',
 * 'user', 'password' — never 'url' — in getConnectionConfig(). See CHANGELOG 0.2.0.
 */
final class TenantAwareDriver extends AbstractDriverMiddleware
{
    public function __construct(
        Driver $wrappedDriver,
        private readonly TenantContext $tenantContext,
    ) {
        parent::__construct($wrappedDriver);
    }

    public function connect(array $params): DriverConnection
    {
        $tenant = $this->tenantContext->getTenant();

        if (null !== $tenant) {
            // Tenant keys win; driver stays consistent (tenant config MUST match landlord driver family).
            $params = array_merge($params, $tenant->getConnectionConfig());
        }

        return parent::connect($params);
    }
}
```

namespace Tenancy\Bundle\Bootstrapper;

 * In database_per_tenant mode, TenantDriverMiddleware wraps the tenant connection's driver
 * and merges the active tenant's getConnectionConfig() at Connection::connect() time.
 * Calling $connection->close() nulls the internal driver-connection reference; the next

{

    {
    }

    public function boot(TenantInterface $tenant): void
    {
        $this->connection->close();
    }

    public function clear(): void
    {
        $this->connection->close();
    }
}

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TenantContext → DBAL driver | Middleware reads the active tenant on every `connect()`. A malicious or misconfigured tenant's `getConnectionConfig()` could in principle merge unexpected keys. |
| DBAL Connection → Tenant DB socket | The decision of which database socket a query hits is made per-connect(), controlled entirely by middleware + TenantContext state. Any `close()`-miss means stale socket leakage. |
| Landlord connection vs. tenant connection | Middleware MUST be scoped to the `tenant` connection only — a tag without `['connection' => 'tenant']` would apply to all connections, corrupting landlord queries. |
