Create `src/Command/TenantInitCommand.php` as a `final class` following the existing command conventions:

1. **Class structure:**
   - `declare(strict_types=1)` at top
   - Namespace: `Tenancy\Bundle\Command`
   - `#[AsCommand(name: 'tenancy:init', description: 'Initialize tenancy configuration')]`
   - `final class TenantInitCommand extends Command`
   - Constructor takes `string $projectDir` (injected as `kernel.project_dir`)
   - Call `parent::__construct()` in constructor

2. **configure() method:**
   - Add `--force` option: `InputOption::VALUE_NONE`, description `'Overwrite existing configuration file'`

3. **execute() method flow:**
   - Create `$io = new SymfonyStyle($input, $output)`
   - Print header: `$io->title('Tenancy Bundle — Configuration Initializer')`
   - Compute target path: `$this->projectDir . '/config/packages/tenancy.yaml'`
   - **Overwrite check:** If file exists AND `--force` not set: print warning with `$io->warning('Configuration file already exists: config/packages/tenancy.yaml')`, print `$io->text('Use --force to overwrite.')`, return `Command::FAILURE`
   - If file exists AND `--force` is set: print `$io->note('Overwriting existing configuration file.')`
   - **Doctrine detection:** Use `class_exists(\Doctrine\ORM\EntityManagerInterface::class)` (consistent with the bundle's existing guard pattern in config/services.php)
   - **Generate YAML content** by calling a private `generateYamlContent(bool $doctrineDetected): string` method
   - **Ensure directory exists:** Create `config/packages/` directory if missing using `mkdir($dir, 0755, true)` guarded by `!is_dir($dir)`
   - **Write file:** `file_put_contents($targetPath, $yamlContent)`
   - Print success: `$io->success('Created config/packages/tenancy.yaml')`
   - **Print driver suggestion:** If Doctrine detected, print `$io->text(['Doctrine ORM detected — recommended driver: <info>database_per_tenant</info>', 'Uncomment driver and set database.enabled: true in your config.'])`. If NOT detected, print `$io->text(['Doctrine ORM not detected — recommended driver: <info>shared_db</info>', 'Install doctrine/orm to use database_per_tenant mode.'])`
   - **Print next steps** by calling a private `printNextSteps(SymfonyStyle $io): void` method
   - Return `Command::SUCCESS`

4. **generateYamlContent(bool $doctrineDetected) method:**
   - Returns a string containing the YAML. The content MUST match the Flex recipe stub's format, with the addition of `tenant_entity_class` and `cache_prefix_separator` config keys.
   - The full YAML content (returned as a PHP heredoc or string):
   ```
   # config/packages/tenancy.yaml
   #
   # Tenancy Bundle Configuration
   # Full reference: https://github.com/danplaton4/tenancy-bundle
   
   tenancy:
       # Isolation driver: database_per_tenant (separate DB per tenant) or shared_db (single DB with SQL filter)
       # driver: database_per_tenant
   
       # Throw TenantMissingException when a #[TenantAware] entity is queried without an active tenant
       # strict_mode: true
   
       # DBAL connection name for the landlord (central) database
       # landlord_connection: default
   
       # Fully-qualified class name of your Tenant entity (must implement TenantInterface)
       # tenant_entity_class: Tenancy\Bundle\Entity\Tenant
   
       # Separator used for tenant cache namespace isolation
       # cache_prefix_separator: ':'
   
       # Enabled resolvers (order = priority: first match wins)
       # resolvers: [host, header, query_param, console]
   
       # HostResolver settings — extract tenant slug from subdomain
       # host:
       #     app_domain: app.example.com
   
       # Database-per-tenant mode (requires doctrine/orm)
       # Set enabled: true to activate two entity managers (landlord + tenant)
       # database:
       #     enabled: false
   ```
   - If `$doctrineDetected` is true, uncomment `driver: database_per_tenant` and `database:\n    enabled: true` lines (remove the `# ` prefix from those specific lines). This makes the config immediately usable for the most common setup.

5. **printNextSteps(SymfonyStyle $io) method:**

         'Configure your host.app_domain if using subdomain-based resolution',
         'Run bin/console doctrine:schema:update or create migrations for the Tenant entity',
         'Visit https://github.com/danplaton4/tenancy-bundle for full documentation',

Use a DIFFERENT environment string to avoid cache collisions with the existing command tests. Use `'command_init_test'` as the environment parameter to CommandTestKernel.

Note: CommandTestKernel's getCacheDir() and getLogDir() include the environment name in the path via `sys_get_temp_dir().'/tenancy_command_test/cache'`. Since they do NOT include `$this->environment`, we must create a subclass `InitCommandTestKernel` that overrides getCacheDir/getLogDir to use a unique path. OR — simpler — just use a different env string. Since the kernel hardcodes the path without env, use the same 'command_test' env but in a separate test process. PHPUnit runs tests in the same process by default.

Actually, looking at the existing test more carefully: `TenantRunCommandIntegrationTest` uses `new CommandTestKernel('command_test', false)` and the cache/log dirs are NOT environment-aware (`sys_get_temp_dir().'/tenancy_command_test/cache'`). The simplest approach is to reuse the same kernel — the container is read-only for these tests.

Structure:

```php
final class TenantInitCommandIntegrationTest extends TestCase
{
    private static CommandTestKernel $kernel;
    private static ContainerInterface $container;

    public static function setUpBeforeClass(): void
    {
        self::$kernel = new CommandTestKernel('command_test', false);
        self::$kernel->boot();
        self::$container = self::$kernel->getContainer();
    }

    public static function tearDownAfterClass(): void
    {
        self::$kernel->shutdown();
    }
```

Test methods:
