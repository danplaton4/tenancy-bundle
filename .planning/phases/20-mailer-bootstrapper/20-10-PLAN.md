<objective>
Close two BOOT-04 sanitization gaps:

**Gap 2 (BLOCKER, REVIEW BL-01)** — `TenantSanitizedTransportException` is an empty subclass that inherits `TransportException::getDebug()` from the parent. Symfony bridges populate `$debug` via `setDebug()` with SMTP transcripts that often include the DSN. The wrapping decorator currently passes the original `TransportException` as `$previous`, so user code calling `$e->getPrevious()->getDebug()` returns the unsanitized payload. Acceptance criterion 5 ("DSN credentials never appear in exception traces or logs") is not airtight.

**Gap (WARNING, REVIEW WR-01)** — `SanitizingMailerDecorator::send` catches only `TransportExceptionInterface`. Bridge-factory throws (`UnsupportedSchemeException`, `Symfony\Component\Mailer\Exception\InvalidArgumentException`) bypass redaction entirely. Widen the catch to `Symfony\Component\Mailer\Exception\ExceptionInterface` and re-throw non-TransportException kinds as `\RuntimeException` (preserves the existing type contract: `TenantSanitizedTransportException` IS-A `TransportException`, so wrapping non-TransportException exceptions in it would change the user-observable type).

**Gap (WARNING, REVIEW WR-07)** — `DsnSanitizer::REDACTION_REGEX` is overly permissive (`[\/]{0,2}` allows zero slashes, matching free-text colons). Tighten to require the literal `://` DSN shape: `/(:\/\/[^:\/@]+:)[^@\/]+(@)/`.

Purpose: airtight "no credentials anywhere" contract — message, debug, message of cause chain, AND non-TransportException error surfaces all flow through DsnSanitizer.

Output: 3 modified `src/` files, 3 augmented test files (the test files already exist — find via `find tests/Unit -name '*Sanitiz*' -o -name 'TenantSanitizedTransportException*'`).

    ```php
    <?php

    declare(strict_types=1);

    namespace Tenancy\Bundle\Exception;

    use Symfony\Component\Mailer\Exception\TransportException;
    use Tenancy\Bundle\Mailer\DsnSanitizer;

    /**
     * Thrown by SanitizingMailerDecorator instead of the underlying
     * TransportException when the DSN password component must be redacted
     * from the message.
     *
     * Extends Symfony\Component\Mailer\Exception\TransportException so user
     * code that catches TransportException (the documented Symfony pattern)
     * still catches this exception — the type contract is preserved.
     *
     * Security invariant (Plan 20-10 / REVIEW BL-01): the parent class
     * exposes getDebug() which Symfony bridges populate with SMTP transcripts
     * that often contain the full DSN string. This subclass overrides the
     * constructor to copy + sanitize the previous TransportException's
     * getDebug() output via DsnSanitizer::redact at construction time. The
     * $previous chain link is preserved (callers walking getPrevious() get
     * the cause chain for stack traces), but the wrapper's own getDebug()
     * always returns a redacted string. Future maintainers: do NOT remove
     * the constructor override — the parent class's getDebug() is a
     * documented data-leak vector per BL-01.
     *
     * Constructor semantics:
     *   - $previous is a TransportException with non-empty getDebug() →
     *     this->setDebug(DsnSanitizer::redact($previous->getDebug()))
     *   - $previous is a non-TransportException (or null) → debug stays ''
     *     (the parent class default).
     */
    final class TenantSanitizedTransportException extends TransportException
    {
        public function __construct(string $message = '', int $code = 0, ?\Throwable $previous = null)
        {
            parent::__construct($message, $code, $previous);

            if ($previous instanceof TransportException) {
                $debug = $previous->getDebug();
                if ('' !== $debug) {
                    $this->setDebug(DsnSanitizer::redact($debug) ?? '');
                }
            }
        }
    }
    ```
