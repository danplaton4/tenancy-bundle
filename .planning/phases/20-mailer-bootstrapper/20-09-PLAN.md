<objective>
Close the BOOT-04 architectural gap documented in 20-VERIFICATION.md (Gap #1) and 20-06-SUMMARY.md ("Issues Encountered"): the existing `TenantMessageDecorator` listens on `MessageEvent`, which fires from `AbstractTransport::send` — AFTER `TenantAwareTransportsDecorator` has made its routing decision. The listener's header writes therefore cannot drive routing in the production code path. The current `AsyncCanaryTest` masks the gap by pre-stamping `X-Transport: tenant_acme` in test code.

This plan introduces a new decorator — `TenantMailerDecorator` — that wraps the `mailer` service (the `MailerInterface`) and stamps `X-Transport`, `From`, and `Reply-To` from the active tenant BEFORE the inner mailer's `send()` runs. Stamping at this position happens BEFORE Symfony's `Mailer::send` decides sync-vs-async, BEFORE Messenger envelope construction, BEFORE PhpSerializer serialization, and BEFORE `mailer.transports` routes — matching exactly what BOOT-04 acceptance bullet (b) describes when it says "stamps X-Transport BEFORE Messenger serialization".

The existing `TenantMessageDecorator` (MessageEvent listener) MUST remain wired as defense-in-depth. It still serves two purposes after this fix: (1) if user code bypasses `MailerInterface::send` and calls a `Transport` directly, the listener still stamps headers; (2) sender-identity headers (`From`/`Reply-To`) on `Email` subclasses sent via paths where only the listener fires.

Also folded in: REVIEW WR-08 (X-Transport mutation footgun) — `TenantAwareTransportsDecorator::send` line 88 currently mutates the caller's message by removing `X-Transport`. Per REVIEW WR-08 recommendation, simply stop removing it. Tenant-specific transports do not re-route based on the header, so leaving it intact is harmless. A regression test verifies re-sending preserves routing.

Purpose: makes BOOT-04 operationally true — zero user boilerplate required for `$mailer->send($email)` to dispatch via the active tenant's SMTP DSN.

Output: 1 new `src/` file, 1 modified `src/` file, 1 modified `config/` file, 1 new unit test file, 3 new test methods added to `AsyncCanaryTest`.
</objective>

Symfony DI ->decorate() semantics (verified against symfony/dependency-injection 7.x):
- Signature: `->decorate(string $id, ?string $renamedId = null, int $priority = 0)`
- HIGHER priority = closer to the original service (= the INNER decorator at runtime).
- Two decorators on the same service: highest priority wraps original first, lower priority wraps that wrapper. So at runtime: lower-priority decorator → higher-priority decorator → original service.
- For this plan: `tenancy.mailer.tenant_decorator` gets `decoration_priority: 10` (INNER, closer to Mailer); `tenancy.mailer.sanitizing_decorator` keeps `decoration_priority: 0` (OUTERMOST, catches exceptions from everything inside).
- Runtime chain: user code → SanitizingMailerDecorator (catches) → TenantMailerDecorator (stamps) → Mailer (Symfony) → mailer.transports → SmtpTransport.

    ```php
    <?php

    declare(strict_types=1);

    namespace Tenancy\Bundle\Mailer;

    use Symfony\Component\Mailer\Envelope;
    use Symfony\Component\Mailer\MailerInterface;
    use Symfony\Component\Mime\Email;
    use Symfony\Component\Mime\Message;
    use Symfony\Component\Mime\RawMessage;
    use Tenancy\Bundle\Context\TenantContext;

    /**
     * Decorates the bundle's MailerInterface (Symfony's Mailer) to stamp the
     * active tenant's X-Transport, From, and Reply-To headers on every
     * outgoing message BEFORE the inner Mailer::send routes it.
     *
     * Stamping at THIS position is the canonical location per BOOT-04
     * acceptance bullet (b) — "stamps X-Transport BEFORE Messenger
     * serialization". The call chain at runtime is:
     *
     *   user code
     *     -> SanitizingMailerDecorator   (decoration_priority 0,  OUTERMOST)
     *     -> TenantMailerDecorator       (decoration_priority 10, INNER)
     *     -> Symfony\Component\Mailer\Mailer
     *        -> mailer.transports (TenantAwareTransportsDecorator)
     *        -> SmtpTransport / Messenger envelope
     *
     * Defense-in-depth note: TenantMessageDecorator (the MessageEvent
     * listener at priority 100) REMAINS WIRED. It catches code paths that
     * bypass MailerInterface::send and call a Transport directly. Both
     * stampers are idempotent — a user-supplied X-Transport header is
     * NEVER overwritten. Future maintainers: do NOT "simplify" by removing
     * the listener — its firing point covers a different surface area.
     *
     * Idempotency contract (mirrored from TenantMessageDecorator):
     *   - X-Transport: stamped only if absent.
     *   - From / Reply-To: stamped only on Email subclasses, only if absent,
     *     and only if the tenant has the corresponding non-null value.
     *
     * Non-Email RawMessage instances receive only X-Transport (no sender
     * identity headers — RawMessage has no headers API of its own; only
     * Message has getHeaders()). Pure RawMessage (no Message parent) is
     * passed through untouched.
     *
     * @see TenantMessageDecorator The MessageEvent listener kept as
     *      defense-in-depth.
     */
    final class TenantMailerDecorator implements MailerInterface
    {
        public function __construct(
            private readonly MailerInterface $inner,
            private readonly TenantContext $context,
        ) {
        }

        public function send(RawMessage $message, ?Envelope $envelope = null): void
        {
            $this->stamp($message);

            $this->inner->send($message, $envelope);
        }

        private function stamp(RawMessage $message): void
        {
            $tenant = $this->context->getTenant();
            if (null === $tenant) {
                return;
            }

            $dsn = $tenant->getMailerDsn();
            if (null === $dsn) {
                return;
            }

            if (!$message instanceof Message) {
                return; // pure RawMessage — no headers API; nothing to stamp.
            }

            $headers = $message->getHeaders();

            if (!$headers->has('X-Transport')) {
                $headers->addTextHeader('X-Transport', 'tenant_'.$tenant->getSlug());
            }

            if (!$message instanceof Email) {
                return;
            }

            $from = $tenant->getMailerFrom();
            if (null !== $from && !$headers->has('From')) {
                $message->from($from);
            }

            $replyTo = $tenant->getMailerReplyTo();
            if (null !== $replyTo && !$headers->has('Reply-To')) {
                $message->replyTo($replyTo);
            }
        }
    }
    ```
