<objective>
Fix the remaining 2 defect sites with a different policy than the 4 resolvers: **fail-loud**. TenantRunCommand and TenantWorkerMiddleware are not chain-fall-through code paths — they perform real, tenant-scoped writes (subprocess spawn for `tenancy:run`; message-bus worker handling for `TenantWorkerMiddleware`). Silently no-op'ing on a null provider would mean dispatching a "tenant-scoped" worker handler with no actual tenant context, or invoking `tenancy:run --tenant=acme` against an unconfigured bundle, both of which would be data-correctness disasters.

Per 18-VERIFICATION.md `fix_strategy`: throw `\RuntimeException` with a descriptive message that names the missing config block + how to fix. The container itself still compiles + the kernel still boots (PHP only instantiates these services when they are actually used — TenantRunCommand only when `tenancy:run` is invoked; TenantWorkerMiddleware only when a Messenger worker processes a message envelope). So fail-loud at use-time does NOT break the zero-config boot path the canary asserts.

Purpose: Close the last 2 defect sites. After this plan, the 18-08 canary should pass all 3 tests (GREEN bar), and a fresh `composer require` + `cache:clear` will succeed cleanly.

Output: 2 modified files; canary GREEN; full test suite stays green.
</objective>

Therefore: change the parameter order is NOT permitted (Symfony container always passes both positional args from `args()`). Instead: declare both positional args, but make the first nullable WITHOUT a default value. Final signature:
       ```
       public function __construct(
           private readonly ?TenantProviderInterface $tenantProvider,
           private readonly string $projectDir,
           private readonly ?\Closure $processFactory = null,
       )
       ```
