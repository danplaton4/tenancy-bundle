<objective>
Fix 4 of the 6 defect sites: HostResolver, HeaderResolver, QueryParamResolver, ConsoleResolver. Each follows the identical pattern — nullable constructor param + early-return null/no-op when the provider is absent. **Fail-silent** is correct here because the resolver chain is a read-only HTTP-request-time chain: when no provider is configured, the resolver simply cannot resolve a tenant, and the chain falls through to the next resolver (or ultimately to null-resolution, which the system already handles per DX-02 Profiler "null-resolution" state).

Purpose: Restore zero-config bootability of the bundle on a fresh `composer require` against a Symfony skeleton. The 18-08 canary test currently RED on this exact site set; this plan flips it to GREEN.

Output: 4 modified resolver files; canary test progresses (fewer TypeErrors); existing 545-test suite stays green.

Both guards are short-circuit early-returns; their relative order does not matter semantically but provider-null first is the convention used by 18-VERIFICATION.md and TenantAwareTransportsDecorator (the already-safe site cited at config/services.php:187).

    4. Keep the existing `try { return $this->tenantProvider->findBySlug($slug); } catch (TenantNotFoundException) { return null; }` blocks intact — once we pass the null guard, `$this->tenantProvider` is non-null and PHPStan-narrowed.

    5.
