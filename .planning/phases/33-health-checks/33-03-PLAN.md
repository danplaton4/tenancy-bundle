<objective>
Build the bundle's FIRST HTTP surface: `TenantHealthController` with live/ready/fleet actions, plus the two importable route files (`config/routes/health.php` for live+ready, `config/routes/health_fleet.php` for fleet — D-02). Responses follow IETF `application/health+json` with the D-05 status->HTTP mapping and the D-06 unknown-slug->404 rule. Every response body is sanitized before serialization.

Purpose: HEALTH-01 (liveness = pure process check, no tenant iteration), HEALTH-02 (readiness = per-tenant probe, 200/503, 404 on unknown slug), HEALTH-06 (bounded fleet endpoint). This is greenfield territory (no prior controller or route files exist in the bundle) — the controller returns plain JsonResponse (no AbstractController/Twig dependency) and routes use PHP-DSL RoutingConfigurator so operators control the mount point (D-01).
Output: `src/Controller/TenantHealthController.php`, `config/routes/health.php`, `config/routes/health_fleet.php`, controller unit tests. DI wiring for the controller service is intentionally deferred to plan 33-05.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated HTTP client -> health endpoint | Health routes are unauthenticated by design (app-level auth is Out of Scope; protection is network-ACL / route-import opt-in per D-01). Untrusted input crosses at the `{slug}` path segment and the `limit`/`offset` query params. |
| readiness/fleet body -> HTTP client | The response body may carry probe exception messages (DSN risk) and, for fleet, the tenant roster (enumeration risk). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-04 | Information Disclosure | ready()/fleet() response body | mitigate | Entire body array passed through `HealthResponseSanitizer::sanitizeArray()` before JsonResponse; unit test asserts a mysql DSN password is redacted to `***`. |
| T-33-ENUM | Information Disclosure | fleet() tenant roster | accept | Fleet enumerates slugs but ships as a SEPARATE importable route (D-02) so operators firewall it independently; importing it is opt-in to disclosure. Bounded by cap+pagination (D-08) so it cannot dump the whole roster in one request. |
| T-33-LIVE-DOS | Denial of Service | live() | mitigate | live() performs zero dependency I/O and never iterates tenants (D-07); a DB outage cannot make liveness fail and trigger a k8s pod-kill loop. Unit test asserts 0 checker/provider calls. |
| T-33-FLEET-DOS | Denial of Service | fleet() | mitigate | limit clamped to `fleet_max_limit` (200) and probing is sequential+bounded (D-08); a huge fleet cannot exhaust DB connections in one request. Unit test asserts `?limit=500` clamps. |
| T-33-SLUG | Input Validation | ready({slug}) | mitigate | Route requirement `slug => [a-z0-9\-]+`; unknown slug resolves via findBySlug throw -> HTTP 404 (V5). |

No npm/pip/cargo installs in this plan — package-legitimacy gate not applicable.
