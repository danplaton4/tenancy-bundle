<objective>
Ship `tenancy:health [--tenant=<slug>|--all] [--format=json]`, the CLI half of the health surface (HEALTH-05). It mirrors `TenantMigrateCommand`: per-tenant streaming output, exit-code aggregation (non-zero if any tenant fails), and a single-aggregate-object JSON mode (D-09). Unlike migrate, the command delegates the set->probe->clear lifecycle entirely to `TenantHealthChecker::checkOne()` — the command loop must NOT clear the context itself.

Purpose: HEALTH-05 — an operator can probe tenant health from the CLI. `--all` is deliberately UNBOUNDED (D-09) because the CLI is an explicit operator action, not an auto-fired probe (bounding is only an HTTP-request-safety concern, D-08).
Output: `src/Command/TenantHealthCommand.php` + unit tests via CommandTester. DI wiring (console.command tag) is intentionally deferred to plan 33-05.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator CLI invocation -> probe engine | The command is an explicit operator action (not an auto-fired probe); `--all` intentionally has no bound. The probe output reaches the terminal / captured logs. |
| probe output -> stdout/logs | Probe exception messages may carry DSNs; they must be redacted before printing (logs are often shipped to third-party aggregators). |

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-33-04 | Information Disclosure | TenantHealthCommand output (txt + json) | mitigate | Every output string routed through `HealthResponseSanitizer::sanitize()` before printing; unit test asserts a mysql DSN password is redacted in both txt and json modes (HEALTH-04). |
| T-33-CLI-CTX | Tampering | command probe loop | mitigate | The command delegates set->probe->clear entirely to `TenantHealthChecker::checkOne()` and takes no TenantContext dependency, so it cannot leak/mutate context; the checker's finally guarantees the clear. |
| T-33-CLI-BOUND | Denial of Service | --all | accept | `--all` is unbounded by design (D-09) — a deliberate operator action, not a per-second probe; no auto-fire risk. Bounding is the HTTP endpoint's concern (plan 33-03). |
