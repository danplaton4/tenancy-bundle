<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| health probe -> global service state | A probe runs under a manually set TenantContext in a shared PHP process; in long-running runtimes (FrankenPHP/Swoole) a leaked TenantContext or a mutated shared Connection would contaminate the next request. |
| bootstrapper exception -> caller | check() may throw a DBAL exception carrying a DSN; healthCheck() must catch it into a result VO, not let it propagate raw. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-33-03 | Tampering / Elevation | TenantHealthChecker::checkOne / TenantContext | mitigate | set->probe->clear-in-`finally`; `boot()` never called. Unit test asserts boot() has 0 invocations; integration test asserts `hasTenant() === false` after success AND failure (Pitfall 8). |
| T-33-STATE | Tampering | DatabaseSwitchBootstrapper::check() global Connection | mitigate | Probe reuses the stateless close()+lazy-reconnect path; integration test proves a subsequent real request reconnects to the correct (different) tenant with no residual state (Success Criterion 2). |
| T-33-PROP | Denial of Service | BootstrapperChain::healthCheck() | mitigate | Each probe wrapped in try/catch -> BootstrapperHealthResult::fromException; a single failing/hanging driver cannot abort the whole health check or crash the request. |

No npm/pip/cargo installs in this plan — package-legitimacy gate not applicable.
</threat_model>
