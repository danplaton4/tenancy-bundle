<objective>
Close CR-01 (nullable-provider drift guard) and WR-01 (Messenger retry semantics).

CR-01: All 6 `tenancy.provider->nullOnInvalid()` consumer constructors must use the identical signature `?TenantProviderInterface $tenantProvider = null`. Today 3/6 (HostResolver, HeaderResolver, QueryParamResolver) have the `= null` default; 3/6 (ConsoleResolver, TenantRunCommand, TenantWorkerMiddleware) do not. Add `= null` to the latter three AND strengthen `NullableProviderInjectionContractTest` to assert both the nullable type AND the default-value presence — reflection-based, no PHPStan rule. Per CONTEXT.md D-02 the PHPStan alternative was rejected.

WR-01: `MissingTenantProviderException extends \LogicException` already exists in `src/Exception/` and is already used by both `TenantRunCommand::execute()` and `TenantWorkerMiddleware::handle()`. The behavioral fix is in place. What is missing is regression coverage: a unit test that asserts the exception is a `\LogicException` (so Symfony Messenger does not retry) for BOTH throwing sites. Add that.

Purpose: Lock the zero-config-boot invariant against drift. The container always passes null via `nullOnInvalid()` so `= null` adds no runtime behavior — but it documents the contract at the type level, locks it via reflection in CI, and makes the signatures identical across all six sites. The LogicException tests prove the Messenger-retry semantic explicitly (today only the source comment claims it).

Output: 3 source files with normalized signatures, 1 strengthened contract test, 2 new exception-class tests.
</objective>
