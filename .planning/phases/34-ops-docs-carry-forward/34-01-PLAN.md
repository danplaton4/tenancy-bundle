<!-- Verified feature surfaces (34-RESEARCH.md §Feature Surface Accuracy). Docs MUST describe these accurately. -->

Parallel migrations (src/Command/TenantMigrateCommand.php):
- `--parallel` (VALUE_NONE, off): bounded subprocess pool; sequential remains default with no flag
- `--concurrency` (VALUE_REQUIRED, default '4'): clamped to [1,32]; values >32 clamp with a notice
- `--dry-run` (VALUE_NONE): compute plan without applying; flows through selected mode
- `--format` (VALUE_REQUIRED, default 'txt'): txt|json; json suppresses human output, stdout carries only the JSON doc
- `--tenant` (VALUE_OPTIONAL, all): single-tenant filter; `--parallel + --tenant` (one tenant) spawns no pool
- shared_db guard: `--parallel` under shared_db returns Command::FAILURE with "parallel migration is not supported under the shared_db driver" BEFORE any subprocess spawns
- null/non-zero subprocess exit = FAILURE (never counted as success); continue-on-failure preserved (all tenants attempted)
- JSON shape: {"tenants":[{"slug","status","migrationsApplied","durationMs","error?"}],"summary":{"succeeded","failed","total","wallClockMs"}}

Maintenance mode (src/EventListener/TenantMaintenanceModeListener.php):
- Listener PRIORITY = 16, fires AFTER TenantContextOrchestrator (priority 20)
- HTTP 503; headers `Retry-After: {seconds}` (default 3600 from tenancy.maintenance.retry_after) and `Cache-Control: no-store, no-cache, must-revalidate`
- Content-negotiated body: JSON {"status":"maintenance","retryAfter":N} if Accept: application/json; else HTML (built-in or custom Twig)
- Allow-list (three OR'd checks): allow_ips (IP/CIDR via IpUtils::checkIp), allow_routes (exact _route match), allow_paths (str_starts_with prefix)
- Commands: tenancy:maintenance:enable <slug> (idempotent), tenancy:maintenance:disable <slug> (idempotent), tenancy:maintenance:status (lists all in maintenance; --format=json)
- BC break: TenantInterface::isInMaintenance(): bool; TenantMaintenanceConfigTrait provides return-false default + in_maintenance column
- Cache-invalidation nuance: DoctrineTenantProvider caches resolved tenants ~300s under `tenancy.tenant.<slug>`; enable/disable commands delete that key after flush so state takes effect on the NEXT request (not after 300s TTL)
- Cross-dependency: /_tenancy/health* prefix MUST be in tenancy.maintenance.allow_paths so probes are never blocked

Health checks (src/Controller/TenantHealthController.php; config/routes/health.php):
- /_tenancy/health/live GET → 200 application/health+json {"status":"ok"} (zero-I/O, no tenant iteration)
- /_tenancy/health/ready/{slug} GET → 200 (pass/warn) / 503 (known-but-unhealthy OR known-but-inactive) / 404 (unknown slug), application/health+json
- /_tenancy/health (fleet) GET → 200 application/health+json paginated (limit default 50, hard max ~200); NOT a k8s probe target — dashboard-only
- Opt-in mechanism: routes exist only when config/routes/health.php (live+ready) and config/routes/health_fleet.php (fleet) are imported; route-import IS the opt-in (no tenancy.health.enabled flag)
- HealthResponseSanitizer redacts any DSN/credential from response bodies before the wire
- CLI: tenancy:health [--tenant=<slug>|--all] [--format=json]; streams per-tenant; exits non-zero if any fail; --all unbounded (operator action, not a probe)
- LiipMonitorBundle: class_exists-guarded auto-register as liip_monitor.check services; absent it, endpoints work unchanged
