**Step 1: Install dev dependencies via Composer CLI:**
```bash
composer require --dev phpstan/phpstan:"^2.1" friendsofphp/php-cs-fixer:"^3.0"
```

Do NOT install `phpstan/phpstan-symfony` — it requires a `containerXmlPath` pointing to a compiled container XML, which does not exist in a standalone bundle (see RESEARCH.md Pitfall 4). The bundle has no container-XML-dependent analysis needs.

Do NOT install `phpstan/extension-installer` — not needed without phpstan-symfony.

**Step 2: Create phpstan.neon** (per D-11: level 9, fixed):
```neon
parameters:
    level: 9
    paths:
        - src
    treatPhpDocTypesAsCertain: false
```

Key details:
- `level: 9` is fixed per D-11 (not `--level=max` which can change between PHPStan versions)
- `paths: [src]` — analyse production code only, not tests
- `treatPhpDocTypesAsCertain: false` — safer for level 9; prevents false positives from imprecise docblocks
- No `includes:` for phpstan-symfony (see Pitfall 4)
- No `excludePaths` needed at this time

**Step 3: Create .php-cs-fixer.dist.php** (Claude's discretion: @Symfony ruleset):
```php
<?php

declare(strict_types=1);

$finder = PhpCsFixer\Finder::create()
    ->in([__DIR__ . '/src', __DIR__ . '/tests'])
    ->name('*.php');

return (new PhpCsFixer\Config())
    ->setRules([
        '@Symfony' => true,
        '@Symfony:risky' => false,
        'declare_strict_types' => true,
        'array_syntax' => ['syntax' => 'short'],
        'ordered_imports' => ['sort_algorithm' => 'alpha'],
    ])
    ->setFinder($finder);
```

Key details:
- `@Symfony` ruleset is the idiomatic choice for Symfony bundles
- `@Symfony:risky` is disabled (Claude's discretion — safer for initial release, per RESEARCH.md Open Question 2)
- `declare_strict_types` enforced (matches existing codebase pattern)
- Finder covers both `src/` and `tests/`

Create `.github/workflows/ci.yml` with these jobs (per D-09, D-10, D-11, D-12):

```yaml
name: CI

on:
  push:
    branches: [master]
  pull_request:

jobs:
  tests:
    runs-on: ubuntu-latest
    name: PHP ${{ matrix.php }} / Symfony ${{ matrix.symfony }}
    strategy:
      fail-fast: false
      matrix:
        php: ['8.2', '8.3', '8.4']
        symfony: ['6.4.*', '7.4.*']
    steps:
      - uses: actions/checkout@v4

      - uses: shivammathur/setup-php@v2
        with:
          php-version: ${{ matrix.php }}
          tools: flex
          coverage: none

      - uses: ramsey/composer-install@v3
        env:
          SYMFONY_REQUIRE: ${{ matrix.symfony }}

      - run: vendor/bin/phpunit

  coverage:
    runs-on: ubuntu-latest
    name: Coverage
    steps:
      - uses: actions/checkout@v4

      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.4'
          tools: flex
          coverage: xdebug

      - uses: ramsey/composer-install@v3
        env:
          SYMFONY_REQUIRE: '7.4.*'

      - run: vendor/bin/phpunit --coverage-clover coverage.xml

      - uses: codecov/codecov-action@v5
        with:
          files: ./coverage.xml
        env:
          CODECOV_TOKEN: ${{ secrets.CODECOV_TOKEN }}

  phpstan:
    runs-on: ubuntu-latest
    name: PHPStan (level 9)
    steps:
      - uses: actions/checkout@v4

      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.4'
          coverage: none

      - uses: ramsey/composer-install@v3

      - run: vendor/bin/phpstan analyse

  cs-fixer:
    runs-on: ubuntu-latest
    name: PHP CS Fixer
    steps:
      - uses: actions/checkout@v4

      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.2'
          coverage: none

      - uses: ramsey/composer-install@v3

      - run: vendor/bin/php-cs-fixer check --diff

  no-doctrine:
    runs-on: ubuntu-latest
    name: No Doctrine (guards check)
    steps:
      - uses: actions/checkout@v4

      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.2'
          tools: flex
          coverage: none

      - uses: ramsey/composer-install@v3

      - name: Remove Doctrine packages
        run: composer remove --dev doctrine/orm doctrine/dbal doctrine/doctrine-bundle doctrine/migrations --no-interaction

      - name: Run unit tests without Doctrine
        run: vendor/bin/phpunit --testsuite unit
```

Key details per each job:

**tests** (per D-12): 3x2 matrix (PHP 8.2/8.3/8.4 x Symfony 6.4.*/7.4.*). Uses `shivammathur/setup-php@v2` with `tools: flex` so `SYMFONY_REQUIRE` env var constrains Symfony versions during `composer update`. Uses `ramsey/composer-install@v3` for proper caching (not raw `composer install` — see RESEARCH.md Pitfall 3). `fail-fast: false` so all combinations are tested even if one fails.

**coverage** (per D-10): Runs on PHP 8.4 + Symfony 7.4 only (latest combo). Uses `coverage: xdebug` to enable code coverage. Uploads `coverage.xml` to Codecov via `codecov/codecov-action@v5`. Requires `CODECOV_TOKEN` GitHub secret (user_setup).

**phpstan** (per D-11): Runs on PHP 8.4 only (no matrix needed for static analysis). Runs `vendor/bin/phpstan analyse` which reads `phpstan.neon` (level 9). No `tools: flex` needed — phpstan doesn't care about Symfony version.

**cs-fixer**: Runs on PHP 8.2 (lowest supported — confirms style is compatible with minimum version). Runs `vendor/bin/php-cs-fixer check --diff` (read-only, not `fix`).

**no-doctrine** (per D-09): Runs on PHP 8.2. First installs all deps, then `composer remove --dev` removes all 4 Doctrine packages, then runs unit tests only. This validates that `class_exists()` and `interface_exists()` guards in the bundle prevent crashes when Doctrine is absent. Only unit tests (not integration) — integration tests require Doctrine.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-07 | Tampering | Third-party GitHub Actions (setup-php, composer-install, codecov) | mitigate | Pin to major version tags (@v2, @v3, @v5) which are maintained by trusted authors; these are the standard actions used across the Symfony ecosystem |
| T-09-08 | Information Disclosure | CODECOV_TOKEN in CI | mitigate | Token stored as GitHub secret, only accessible in the workflow context; codecov-action uses HTTPS for upload |
| T-09-09 | Denial of Service | CI matrix running 6+ jobs on every PR | accept | Standard practice for OSS; GitHub Actions free tier for public repos is sufficient |
</threat_model>
