**5. Architecture Overview** (per D-05):
Section header: `## How It Works`

Brief explanation (1-2 paragraphs + a flow diagram in text):
1. A `kernel.request` listener at priority 20 triggers the resolver chain
2. The resolver chain identifies the tenant (subdomain, header, etc.)
3. `TenantResolved` event fires, `BootstrapperChain` runs all registered bootstrappers
4. Each bootstrapper reconfigures its subsystem (DB connection, cache namespace, etc.)
5. `TenantBootstrapped` event fires, request proceeds with full tenant context
6. On `kernel.terminate`, context is cleared and `TenantContextCleared` fires

Show a simple text flow:
```
Request -> Router -> TenantContextOrchestrator (priority 20)
                          |
                    ResolverChain
                          |
                  TenantResolved event
                          |
                  BootstrapperChain.boot()
                   - DatabaseSwitchBootstrapper
                   - DoctrineBootstrapper
                   - CacheBootstrapper
                          |
                  TenantBootstrapped event
                          |
                    Controller runs
```
