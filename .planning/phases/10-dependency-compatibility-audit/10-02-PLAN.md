**Step 1: Add prefer-lowest job (per D-09)**

Add a new job named `prefer-lowest` to ci.yml after the existing `no-doctrine` job. This catches floor constraint violations by installing the oldest compatible versions:

```yaml
  prefer-lowest:
    runs-on: ubuntu-latest
    name: Prefer Lowest
    steps:
      - uses: actions/checkout@v4

      - uses: shivammathur/setup-php@v2
        with:
          php-version: '8.2'
          tools: flex
          coverage: none

      - uses: ramsey/composer-install@v3
        with:
          composer-options: --prefer-lowest --prefer-stable
        env:
          SYMFONY_REQUIRE: '7.4.*'

      - run: vendor/bin/phpunit
```

Key design decisions:
- PHP 8.2: the floor PHP version, so we catch issues with the oldest supported PHP
- `SYMFONY_REQUIRE: '7.4.*'`: ensures Symfony Flex constrains to 7.4.x (the LTS floor)
- `--prefer-lowest --prefer-stable`: Composer resolves to the oldest stable version within each constraint
- Runs full test suite (not just unit) to catch integration issues with old dependency versions

**Step 2: Add no-messenger job (per D-10)**

Add a new job named `no-messenger` to ci.yml after the `prefer-lowest` job. This mirrors the existing `no-doctrine` pattern to validate interface_exists guards for Messenger:


Key design decisions:
- PHP 8.2: lowest supported PHP version (consistent with no-doctrine)
- `composer remove --dev symfony/messenger`: removes the package so Messenger interfaces are absent
