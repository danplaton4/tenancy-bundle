**Step 1: Add SYMFONY_DEPRECATIONS_HELPER to phpunit.xml.dist (per D-05)**

Add a `<php>` block to `phpunit.xml.dist` after the closing `</source>` tag and before `</phpunit>`:

```xml
    <php>
        <env name="SYMFONY_DEPRECATIONS_HELPER" value="max[direct]=0"/>
    </php>
```

This catches direct Symfony deprecation notices in the bundle's own code. The `max[direct]=0` value means zero tolerance for deprecations the bundle directly triggers, while allowing indirect deprecations from vendors (the default behavior).

The `symfony/phpunit-bridge` (already in require-dev) reads this env var and converts deprecation notices into test failures. This ensures any Symfony API the bundle uses that gets deprecated in 8.x will be caught immediately.

**Step 2: Run PHPStan with --php-version=80200 (per D-08)**

Run `vendor/bin/phpstan analyse` to verify clean analysis. PHPStan level 9 is already configured in phpstan.neon. This confirms no PHP-version-specific issues exist.

**Step 3: Run full test suite to verify deprecation helper works**

Run `vendor/bin/phpunit` to confirm:
1. All existing tests still pass
2. No direct Symfony deprecation notices are triggered
3. The SYMFONY_DEPRECATIONS_HELPER env var is picked up correctly by phpunit-bridge

If indirect deprecation noise from Doctrine or other vendors causes failures, update the value to `max[direct]=0&max[indirect]=999` to allow vendor deprecations while still enforcing zero direct deprecations.
