<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Packagist → end-user `composer install` | nikic/php-parser is downloaded transitively when end users install this bundle. Threat surface: supply-chain. |
| Docs reader → install command | Users follow docs to run `tenancy:install`. Threat surface: docs accuracy (incorrect instructions → unbootable bundle). |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-01 | Tampering (supply-chain) | `nikic/php-parser` moves from `suggest` to `require`. End users now transitively install this package. | accept | Mitigated by maturity: nikic/php-parser is widely used (PHPStan, Psalm, Rector, Sulu all depend on it). Pinned to `^5.0`. End-user composer.lock provides reproducibility. Severity LOW. |
| T-22-02 | Repudiation/Tampering | Stale docs instructing users to manually edit bundles.php causes inconsistent install state | mitigate | This plan rewrites the install path completely and a downstream plan (Plan 06) adds a `scripts/docs-lint.sh` check that fails CI on regression. |
| T-22-SC | Tampering | npm/pip/cargo installs | n/a | No package-manager installs in this phase; composer.json edit is a manifest change only (no runtime install). Package legitimacy gate not triggered. |

**Severity overall: LOW.** No code paths added, no auth changes, no input handling.
</threat_model>
