    Extend `scripts/docs-lint.sh` per RESEARCH §"docs-lint awk Pattern" Approach A.

    **Insertion point:** AFTER the existing 5 `check` calls (lines 38-42) and BEFORE the success-message gate (lines 44-46).

    **What to add** (use the exact awk pattern from RESEARCH; this is the load-bearing piece):

    ```bash
    # D-15: fail on bundles.php install-path references in docs/
    # Whitelisted H2 sections (legitimate references stay in these scopes):
    #   - Migration
    #   - Upgrade
    #   - Manual setup
    #   - Troubleshooting
    #   - Do I have to do anything?
    # Implementation: awk tracks current H2 heading; lines in whitelisted sections are filtered out before grep.

    BUNDLES_VIOLATIONS=$(awk '
        /^## / {
            section = $0
            sub(/^## /, "", section)
            in_whitelist = (section ~ /^(Migration|Upgrade|Manual setup|Troubleshooting|Do I have to do anything\?)/)
            next
        }
        !in_whitelist { print FILENAME ":" FNR ":" $0 }
    ' $(find docs/ -name '*.md') | grep -nE 'bundles\.php' || true)

    if [ -n "$BUNDLES_VIOLATIONS" ]; then
        echo "ERROR: 'bundles.php' install-path reference found in docs/ outside whitelisted sections (Migration / Upgrade / Manual setup / Troubleshooting / Do I have to do anything?)."
        echo "$BUNDLES_VIOLATIONS"
        EXIT=1
    fi
    ```

    **Notes on the implementation:**
    - The `find docs/ -name '*.md'` enumerates all docs markdown files. The awk script receives them as arguments (relies on file count being reasonable — a few dozen docs files, no risk of arg-list-too-long here).
    - `next` after the section detection ensures heading lines themselves never reach the grep stage — only body lines.
    - The `|| true` after grep prevents the pipeline failure from killing the script before `$BUNDLES_VIOLATIONS` is checked (grep returns 1 when no matches; we WANT no matches as the success case, so `|| true` swallows that exit code).
    - `EXIT=1` follows the existing pattern in the file.

    **Important:** Approach A widens beyond CONTEXT D-15's literal text (D-15 says only "Migration / Upgrade"). This is justified by RESEARCH Open Q1: profiler-tab.md's `bundles.php` references at L22, L35, L125, L135 live under `## Do I have to do anything?` and `## Troubleshooting` headings — they describe the OPTIONAL web-profiler-bundle install, NOT the tenancy install. Restructuring profiler-tab.md to fit a narrower whitelist would be more disruptive than widening the whitelist. **Add a comment block in `scripts/docs-lint.sh`** documenting WHY the whitelist is wider than D-15's literal text — future authors need this context.
