<objective>
Replace the Plan 01 skeleton of `SharedEntityLeakRule` with the full Rule 2 implementation: a `MethodCall`-node rule that fires when a concrete tenant/default EntityManager queries a `#[Shared]` entity — the static-analysis catch for a cross-tenant data leak. Per D-03 the rule is conservative/precision-first: it fires only when the EM and the queried `#[Shared]` entity are BOTH unambiguous, and stays silent on an ambiguous `EntityManagerInterface` caller and on the named landlord EM path. Per D-01 it is gated behind the `tenancy.checkSharedEntityLeaks` parameter (default true, injected from `extension.neon`). Suppression identifier: `tenancy.sharedEntityLeak`.

Purpose: A `#[Shared]` entity is a landlord-side master; querying it through the tenant EM is the data-leak pattern Rule 2 catches before it ships (DX-03-AC2). Precision keeps the rule enabled in real CI (a rule that cries wolf gets toggled off).
Output: Working Rule 2 + test (fires / gated-off / conservative-silent) + fixtures.
</objective>
