<objective>
Close Gap 1 (CR-01, BLOCKER) and Gap 3 (WR-02, WARNING) from 28-VERIFICATION.md, and fold in WR-04 — all of which live in `src/PHPStan/Rule/TenantIdDriftRule.php` and its test. Consolidating every change to these two files into one plan avoids the file-conflict serialization that would otherwise force Gaps 1 and 3 into separate waves.

Gap 1 (CR-01): `checkViaMetadata()` is broken on Doctrine ORM 3.x — `FieldMapping` entries are objects implementing `ArrayAccess`, not arrays, so the `if (!is_array($mapping)) continue;` guard skips every mapping and fires a false "no tenant_id column" on every valid `#[TenantAware]` entity. Fix via `$metadata->fieldMappings` (narrowed with an object-shape `@var` to stay level-9 clean) and the ArrayAccess offset accessor (`$fm['columnName']` / `$fm['nullable']` / `$fm['type']`), which also resolves IN-02 (the brittle `(array) $metadata` cast). Add a RuleTestCase test that constructs the rule WITH a real `ObjectMetadataResolver` so the metadata path is exercised in CI (its zero coverage is why CR-01 shipped).

Gap 3 (WR-02): the rule false-fires on `#[TenantAware]` `#[ORM\MappedSuperclass]` / abstract bases that legitimately defer `tenant_id` to concrete subclasses. Skip abstract + MappedSuperclass classes (when no tenant_id is in their own hierarchy) and correct `testFiresOnInheritedTenantAware()` so the MappedSuperclass parent is SILENT while a concrete child still fires.

WR-04 (folded): `evaluateFinding()` / `checkViaReflection()` read only NAMED `nullable`/`type` args on `#[ORM\Column]`; positional args silently pass. Read positional args too so a positionally-declared drift isn't missed.

Purpose: the D-02 metadata path is the consumer-facing feature the bundle advertises in `composer.json` suggest; shipping it broken (false-positive storm) trains consumers to suppress the rule, defeating its leak-detection value (security-relevant). WR-04 closes the one false-negative direction.
Output: ORM-3.x-correct Rule 3 + metadata-path test coverage + MappedSuperclass exemption + corrected hierarchy test + positional-arg reading.
