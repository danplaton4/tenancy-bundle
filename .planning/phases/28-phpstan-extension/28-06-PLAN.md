<objective>
Close Gap 2 (WR-01, BLOCKER) from 28-VERIFICATION.md and fold in WR-05. This plan depends on 28-05: the CR-01 FieldMapping fix MUST land first, because wiring the resolver before the fix would immediately expose consumers to the false-positive storm (REVIEW.md WR-01: "Until CR-01 is fixed, wiring this would expose the FieldMapping bug — fix CR-01 first, then wire").

Gap 2 (WR-01): `TenantIdDriftRule` is registered in `extension.neon` with no `arguments`, and PHPStan's Nette DI container cannot autowire a `?object`-typed parameter to the concrete `ObjectMetadataResolver` service — so `$this->objectMetadataResolver` is always null even with phpstan-doctrine installed, and the advertised "XML/YAML-mapped entity analysis" (composer.json suggest) silently does nothing. The fix is to inject `@PHPStan\Type\Doctrine\ObjectMetadataResolver`. Because that `@service` reference is resolved at config-merge time and would crash when phpstan-doctrine is absent, the wiring MUST live in a conditionally-included neon fragment — the base `extension.neon` stays resolver-less for the degrade-to-reflection path (D-02).

WR-05 (folded): CI never exercises the optional-dependency guards — the `no-doctrine` job runs only a hand-listed set of unit dirs and never runs PHPStan, the dogfood, or `tests/Unit/PHPStan`. A regression that hard-references a Doctrine class at class-load time would pass all current CI. Extend the `no-doctrine` job to run a base-only dogfood + `tests/Unit/PHPStan` without Doctrine.

Purpose: WR-01 makes the D-02 "present" path live (truth #10) so the soft-integration the user locked actually functions; WR-05 locks in the optional-dependency contract that is the bundle's defining identity (Doctrine guarded-optional). Together with 28-05 they make the metadata path correct, wired, AND tested.
Output: a conditionally-included doctrine wiring fragment + a dogfood that runs the wired path + a base-only dogfood + a no-doctrine CI lane proving graceful degradation.

  registered for the wired dogfood run; no PHPStan dedup is relied upon. The base extension.neon remains the SOLE source
