<objective>
Wire the Phase 25 components into the container and prove the full SHARE-01 suite GREEN, then document the shared_db no-op. This plan connects the leaf primitives (25-01), the compiler pass (25-02), and the subscribers (25-03) into a working feature.

**Open-question A2 resolution (shared_db + connection tag):** the subscriber and write-protection listener are connection-scoped (`landlord` / `tenant`). Under `shared_db` there is no `landlord`/`tenant` connection — only `default` — so a `connection: landlord` tag would reference a non-existent connection. Resolution: register both services INSIDE the `if ($databaseConfig['enabled'] ?? false)` block in `TenancyBundle::loadExtension()` (the `database_per_tenant` path that actually creates the landlord+tenant connections), mirroring the precedent at `TenancyBundle.php:208-254` (TenantDriverMiddleware is registered there with `['connection' => 'tenant']`). Under `shared_db` the services are simply never registered → no missing-connection error, and the D-03 runtime short-circuit in the subscriber is belt-and-suspenders. This is cleaner than registering in `services.php` (which always runs regardless of driver). The mutual-exclusion compiler pass, by contrast, registers unconditionally in `build()` (guarded only by `interface_exists`) like every other ContractPass.

Purpose: make the feature live and assert the wiring contract (landlord-only subscriber).
Output: modified `src/TenancyBundle.php`, the docs no-op note; `config/services.php` only if the executor chooses to centralize definitions there (see action note).
</objective>
