**Status:** ✅ SHIPPED 2026-05-29

## Overview

v0.3 was the **Adoption Surface** milestone: turn the Packagist page into a successful first install. v0.2 shipped to two self-installs and zero external dependents; v0.3 attacked the install funnel and shipped the highest-leverage missing features.

**What v0.3 delivered:**
- One-command bundle setup (`bin/console tenancy:install`) — no manual `config/bundles.php` editing
- Per-tenant Mailer bootstrapper correct under BOTH sync and async (Messenger) dispatch
- Symfony Profiler "Tenancy" panel with three render states (resolved / null / error)
- SPA-friendly OriginHeaderResolver at priority 25 with browser-locked allow-list
- Runnable two-tenant demo (`examples/saas/`) with FrankenPHP + Caddy + MariaDB, gated as CI release-smoke
- Docs refresh — new pages for resolver/profiler/mailer/demo + UPGRADE 0.2→0.3 + canonical roadmap mirrored to docs site
- Audit-driven tech-debt closure (Phase 23) — Profiler/Mailer Twig contract drift, WR-01 LogicException semantics, smoke.sh mailer assertion, CHANGELOG promotion

**Architectural decisions ratified (DEC-* IDs in `v0.3-REQUIREMENTS.md`):** DEC-MAIL-01 X-Transport strategy, DEC-MAIL-02 full BOOT-04 in v0.3, DEC-MAIL-03 BC break with trait, DEC-RESV-01 priority 25, DEC-PROF-01 TenantResolved subscriber, DEC-INST-01 programmatic invoke, DEC-INST-02 refuse-on-nonstandard, DEC-DEMO-01 Caddy + `*.tenancy.localhost`.

**Explicit non-goal:** Symfony Flex recipe. `tenancy:install` is the supported onboarding path; revisit `symfony/recipes-contrib` only when install volume justifies the maintenance cost.

## Milestone Summary

**Key Decisions:**

- **DEC-MAIL-01:** Mailer extension point = `X-Transport` header strategy + `MessageEvent` listener for `From`/`Reply-To`. Validated by AsyncCanaryTest proving tenant A's DSN survives Messenger round-trip.
- **DEC-MAIL-02:** Full BOOT-04 scope landed in v0.3 (not split across milestones).
- **DEC-MAIL-03:** `TenantInterface::getMailerDsn()` is a BC break, mitigated by `TenantMailerConfigTrait` migration recipe in UPGRADE.md.
- **DEC-RESV-01:** OriginHeaderResolver priority 25 (between HostResolver 30 and HeaderResolver 20). Validated by smoke.sh runtime assertion.
- **DEC-PROF-01:** Profiler resolved-by plumbing via TenantResolved event subscriber — keeps TenantContext zero-dependency contract intact.
- **DEC-INST-01:** `tenancy:install` invokes `tenancy:init` programmatically (forwards `--force`). Single continuous transcript.
- **DEC-INST-02:** Non-standard `bundles.php` shapes — refuse to mutate, print manual snippet, exit 0. Refusal is clean exit, not failure.
- **DEC-DEMO-01:** Demo subdomain routing via Caddy + `*.tenancy.localhost` + internal CA + three-step fallback ladder.
- **AbstractTenant split (Phase 21 BOOT-01):** Bundle Tenant split into AbstractTenant (MappedSuperclass) + thin concrete Tenant. Doctrine ORM refused two `#[ORM\Entity]` roots on `tenancy_tenants` table. BC break for downstream users extending Tenant — documented in UPGRADE 0.3.1→0.3.2.
- **Phase 23 audit-driven closure:** Confirmed the pattern of running `/gsd:audit-milestone` then inserting a closure phase + refresh sweep before tagging. Found two stale-audit cases (CR-01 + IN-05) where the audit prescription conflicted with already-shipped state.

**Issues Resolved:**

- **Zero-config kernel boot regression** (Phase 18 gap closure 2026-05-21): 6 `nullOnInvalid()` consumer sites had non-nullable signatures. Bundle was unbootable in zero-config mode. Closed via 4 gap-closure plans + permanent ZeroConfigKernelBootTest canary regression coverage.
- **Phase 20 mailer X-Transport routing** (Phase 20 Run 2 verification 2026-05-20): Initial `TenantMessageDecorator` listener-based stamping fired AFTER routing. Closed by introducing `TenantMailerDecorator` at decoration_priority 10 (INNER) — stamps X-Transport / From / Reply-To BEFORE Mailer routes. Defense-in-depth: TenantMessageDecorator retained at priority 100.
- **DSN credential leak via getDebug** (Phase 20 BL-01 closure): `TenantSanitizedTransportException::getDebug()` could leak unredacted DSNs. Constructor override + DsnSanitizer regex tightened (require literal `://` shape) + load-bearing regex test invariant.
- **Demo live-stack boot blockers** (Phase 21 Pass 3 2026-05-22): 7 latent BOOT-* bugs that no prior code-only verification had caught. Live `docker compose up` was a structural verification gap. Closed by 8 commit fixes + structural recommendations for future phase verification contracts.
- **Stale audit findings (CR-01, IN-05) in Phase 23**: Audit prescribed reversing commit 31465dc and adding an import that cs-fixer strips. Caught by executor agents during cross-check; both items downgraded to documentation. Recommendation surfaced: `/gsd:discuss-phase` should `git log --since=<audit-date>` over files named in canonical_refs before generating closure CONTEXT.md.

**Issues Deferred:**

- **22-HUMAN-UAT.md (4 items)**: `mkdocs --strict` CI gate, ASCII visual rendering in MkDocs Material light+dark, post-publish docs-site URL verification, cross-tree link rendering. None block tag — mkdocs runs in CI on the push.
- **Live-stack demo verification in 23-07**: `examples/saas/composer.lock` resolved Symfony components to v8.0.x (requires PHP ≥8.4), but `examples/saas/Dockerfile` installs PHP 8.2. Pre-existing demo lockfile/runtime drift, out of scope for Phase 23 (single-file plans). Deferred — `.github/workflows/demo-smoke.yml` runs in CI.

**Technical Debt Incurred:**

- `examples/saas/composer.lock` vs `Dockerfile` PHP version drift (noted in 23-04-SUMMARY) — refresh in early v0.4.
- Phase 22 `docs/examples/saas-demo.md` cross-tree link to `../../examples/saas/README.md` is a known MkDocs landmine (acceptable trade-off per RESEARCH §Landmines #1; renders differently on docs-site vs GitHub UI).
- Phase 19/20 Mailer subsection visibility on null/error states was the INT-01 audit finding — fixed in Phase 23, but the underlying Twig discipline (data layer collects in all states; presentation layer hides on non-resolved) is worth a project convention note for future collectors.
